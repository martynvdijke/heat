# TRMNL Compact Layouts — Design

## Context

- The TRMNL plugin lives at `trmnl/` as a trmnlp project (`.trmnlp.yml` + `src/`), deployed via the `trml` job in `release.yaml` (see the `trmnl-ci-pipeline` change). The `/api/trmnl/summary` payload shape is fixed: `latest_race` (`round`, `track`, `country`, `name`, `race_date`, `total_laps`, `results[{position, racer_name, points}]`), `standings` (`[]SeasonStanding` with `racer_name`, `races`, `wins`, `points`), and `season` (`{id, name}`). `models.SeasonStanding` is serialized directly (`Wins` carries `json:"wins"`), so the templates can read `standing.wins`.
- The previous templates used TRMNL's default tokens (`gap`, `value--large/medium/small`, `grid--cols-1`, `hr`) and split results into "top 3" and "rest" grids. On the 800x480 device the full layout overflowed; the compact class system (`gap--xsmall`, `label--small`, `value--xsmall/xxsmall`, `divider--h`, `grid--cols-2`) was introduced to fix this.
- This change documents work applied in commit `8c267dd` ("fix: make TRMNL plugin layouts compact and readable on 800x480").

## Goals / Non-Goals

**Goals:**
- Every layout renders without overflow on the 800x480 e-ink display.
- Consistent, readable typography hierarchy across all four layouts.
- Clear fallback UI when there is no race or standings data.
- No changes to the `/api/trmnl/summary` payload or the Go backend.

**Non-Goals:**
- New data fields or endpoints (payload is unchanged; templates only consume existing fields).
- Changes to the CI/deploy workflow (`trmnl-ci-pipeline` is untouched).

## Decisions

### D1: Compact design tokens everywhere
All four layouts use `gap--xsmall`, `label--small`, `value--xsmall` (secondary) and `value--xxsmall` (dense rows), `divider--h` between sections, and `grid--cols-2` for dense two-column rows. Consistent tokens keep the layouts visually uniform and fit the 800x480 screen.

### D2: Top-3 focus in small layouts, full results on full
- `half_horizontal`, `half_vertical`, `quadrant`: `forloop.index <= 3` for both race results and standings — the small viewport cannot show every row legibly.
- `full`: all race results and standings render in a `grid--cols-2` layout, each cell showing position + name and points (standings rows also show wins in half_horizontal).

### D3: Fallback states
Each layout renders `No race data yet` when `latest_race` is nil and `No standings yet` when the standings array is empty (`standings.size == 0` / `elsif latest_race == nil`), so a cold plugin or empty season never renders blank.

### D4: Simplified title bar
The title bar is text-only: `Heat{% if season %} - {{ season.name }}{% endif %}`. The image was removed (it added no information and consumed vertical space). No custom-field URL is needed since no images remain.

### D5: Build output ignored
`trmnl/.gitignore` ignores `_build/` (generated by `trmnlp build`), keeping the plugin project tree clean.

### D6: Payload compatibility
Templates reference only fields already present in the summary payload (verified against `handlers/trmnl.go` and `models.SeasonStanding`): `latest_race.*`, `standings[].{racer_name, wins, points}`, `season.name`, and the `size`/`nil` Liquid checks. No backend change required.

## Risks / Trade-offs

- [Template only shows top 3 on small layouts] → intentional for readability on 800x480; full results remain available in the `full` layout.
- [`wins` shown only in half_horizontal standings] → minor inconsistency across layouts, accepted for density; `wins` is part of the payload everywhere.
- [Redesign must still pass `trmnlp lint`] → the `trml` job (see `trmnl-ci-pipeline`) enforces this on every PR/release; any regressions fail CI before deploy.
